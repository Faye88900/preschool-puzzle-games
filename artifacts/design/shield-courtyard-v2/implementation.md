# 盾兵庭院实机优化 · 2026-10-22

本轮按 `concept.png` 实现第二只盾兵的庭院美术。运行模块为 `src/shield-courtyard.ts`，由 `src/wind-garden.ts` 创建；`src/maze.ts` 加载贴图、注册碰撞与镜头遮挡，并连接击败状态。未新增第三方依赖。

## 已落实的场景

- 平整圆形风叶纹石地：约 14.3 单位直径，中央无凸起碰撞，保留两侧闪避。
- 叶盾徽石龛、错落断墙和残柱，搭配藤蔓、小风铃与靠墙备用盾牌，形成守卫据点。
- 四个石沿花池、野花、蕨类和分层树冠，集中在外围。
- 降低入口拱门，并按反馈对齐通道中线；立柱支撑拱圈两端的厚度中心，拱圈与立柱共用同一定位。PC、窄屏和横屏的镜头射线确认拱门不会挡住盾兵身体。
- 击败第二只盾兵后，徽章叶脉提高亮度，六片薄叶纹沿右出口出现；重置后熄灭并隐藏。
- 引导叶纹从庭院内部开始，采用独立的薄荷绿无光照材质，在浅色铺地上保持可见；不会让外围植物一起变亮。
- 外围实体使用简化碰撞，仍使用原地图、原地板与敌人避障系统。

后续长花园路、凉亭左侧朝右的拟人花坛，以及码头乘船到独立 Boss 岛的路线继续沿用。没有把 Boss 放到这座庭院。

## 资产来源与技术美术约束

| 表面 | 方式 | 产物或实际限制 |
| --- | --- | --- |
| 风叶石地 | 原创 ImageGen + 现有材质 | `floor-source.png` → `public/textures/maze/courtyard-wind.webp`，1024²、204198 字节；sRGB、粗糙度 1、各向异性最大 4 |
| 叶盾徽石龛 | 定制 Three.js 几何 | Tripo 凭证探测 `TRIPO_API_KEY=SET`；生成请求实际返回 HTTP 403、code 2010、`You don't have enough credit to create this task`，没有生成任务 ID 或下载模型，因此采用自建模型 |
| 断墙、入口、花池、植物、路牌 | 定制几何，按材质合批 | 重复花瓣、叶片与树冠共享几何和材质；支撑物不需要独立外部模型；纹样由独立生成贴图承担 |
| 战后提示 | 少量独立几何 | 徽章叶脉和地面引导叶片由盾兵 hp 驱动，不增加灯光、后期处理或粒子系统 |

材质保持暖米白石、深浅绿植、少量粉白花和克制的青铜。沿用游戏原有阳光、阴影、DPR 与色调映射。支撑物按材质合批，带 UV 的地面在合批后单独加入；胜利信号与遮挡组件保持独立。

参考账本：已读取 `threejs-aaa-graphics-builder` 的 `visual-scorecard.md`、`implementation-blueprint.md`、`model-recipes.md`、`render-recipes.md`、`technical-art.md`，以及程序模型、材质灯光、性能细节检查表。已读取 3D 生成与图像生成技能后进行资产选择。这里交付局部庭院美术改造，不作全游戏 AAA 或发布就绪评级。

局部对比：旧图缺少后景地标、中央铺地主题和战后方向反馈；新图形成叶盾石龛、风纹拼花与右行叶纹三层识别点。第一轮截图暴露拱门挡敌、空花池和树冠单薄，已降低拱门、填充花池并增加树冠层次。随后根据拱门偏斜反馈，将中心从 x=24 修正为通道的 x=25，并将柱距匹配到拱圈厚度中心；中线直行与柱体阻挡纳入现有实测。

实机存档：`after-pc.png` 为鼠标 PC 战斗视角，`after-victory-pc.png` 为战后引导，`after-mobile.png` 为触屏竖屏；均为 Three.js 实际渲染，概念图只存为 `concept.png`。
